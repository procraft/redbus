# ReadmeAI — контекст модуля

`ReadmeAI.md` — локальная заметка о модуле (архитектура, роуты, хранилища, соглашения об именовании,
локальные подводные камни). Имя файла ровно такое, регистр важен.

## Читать перед работой

Перед началом содержательной работы в папке фичи (новая задача, рефакторинг, незнакомый участок кода):

1. Начинать с каталога, который является основной областью изменения: папка редактируемого файла или
   путь, на который указал пользователь.
2. Если `ReadmeAI.md` там нет — идти вверх по родительским каталогам до корня workspace.
3. Использовать ближайший `ReadmeAI.md` — это самая специфичная заметка о модуле. Если задача
   затрагивает несколько поддеревьев, проверить каждый корень отдельно.
4. Прочитать его на этапе планирования правок, а не после.
5. Если в цепочке `ReadmeAI.md` нет — работать обычным исследованием кода; наличие файла не
   обязательно.

## Обновлять после работы

После задачи, которая меняет бизнес-логику, архитектуру, поток данных, контракты API или неочевидные
краевые случаи:

1. Найти ближайший `ReadmeAI.md` (в модуле или выше).
2. Оценить, затронула ли правка что-то из перечисленного.
3. Если да — предложить краткое обновление: только значимое и неочевидное, без пересказа кода,
   объясняя «почему» и «как», а не «что». Сказать об этом в финальном ответе самому, не дожидаясь
   вопроса пользователя.
4. Если `ReadmeAI.md` нет, а у области накопился повторяющийся контекст (роуты, хранилища,
   интеграции) — предложить создать файл с минимальной структурой и упомянуть это в финальном ответе.
5. По умолчанию изменения `ReadmeAI.md` подаются как предложение (диф). Создавать или править файл
   напрямую — только если пользователь явно попросил применить обновление.
